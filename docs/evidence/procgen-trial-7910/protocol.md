# Fixed protocol: workbench-selection-repair.v1

Frozen before collecting agent submissions. This is a small feasibility trial,
not a powered comparison of models or a claim that contract satisfaction measures
fun. Twelve resolved candidates cover three existing motifs, seeds 11 and 29,
and passing/failing versions of each. Every lane receives the same retained bank
and the same omniscient inspection tool. IDs are neutral bookkeeping, not concealment
of facts in the resolved candidate or analysis.

## Main comparison

Choose exactly one candidate for each motif. Prefer technical validity first,
then explain the choice among working alternatives. Selection and editing receive
the same objective; editing is allowed, not required. A zero-edit answer is valid.

- Deterministic: first passing ID for each motif, sorted ordinally.
- Agent selection: choose existing candidates, no edits.
- Agent editing: choose candidates, with at most one applicable canonical repair
  per selected candidate. Operations are restore-switch, restore-recovery and
  restore-preview. No room, route, schema, evaluator or acceptance edits.

Acceptance is fixed by C#: completion, zero unrecoverable reachable states, and
all existing motif contracts passing. An agent cannot submit new acceptance
fields. Actual world checks and human impressions remain separate evidence.
Raw submissions and canonical evaluated copies are retained alongside results.
Each agent gets at most four minutes and a bounded task, and may inspect the bank
and use the supplied CLI. It must not read other lanes' outputs or product source.
A single agent run per lane is exploratory, not statistical evidence.

## Separate repair challenge and adversarial probes

After the main submissions are frozen, present the editing agent one selected
failed parent per motif. Require one repair each and retain their canonical
receipts. Report this separately: forcing failed inputs would bias the main
selection-versus-editing comparison.

Retain unedited failed selections as negative controls with their executable
counterexamples. Probe an accepted physical sample for an unintended route in a
separate, explicitly informed exploit scenario. Solution-blind exploration uses
only native scene observations and ordinary controls, without candidate maps,
witnesses, source or debug readouts. It cannot serve as exhaustive verification.

## Metrics and limits

Report accepted choices, accepted distinct resolved identities, covered motifs,
room/passage structure hashes, route-condition pattern hashes, and canonical
repair-field cost. Structure hashes use only resolved rooms/routes; seed,
mechanic labels and repairable flags do not count as new room/passage structure.
Pattern hashes omit dimensions. These are bounded exact signatures, not graph
isomorphism or human-perceived diversity. All candidates still have four rooms
and one cycle; three mechanics do not create three novel spatial topologies.

Record observed decision wall time separately from evaluator runtime. Wall time
includes orchestration and is not billed token usage. Record monetary/token cost
as unavailable unless actual harness telemetry supplies it. Do not invent a
conversion from repair fields or elapsed time to money. Cost per accepted distinct
*enjoyable* level remains null until human judgments and the relevant cost measure
exist. Repair fields per technically accepted identity is a different metric.

## Human blind calibration

Present deduplicated output candidates under B01, B02, … without lane or repair
labels. Keep the assignment key separate from the participant instructions.
Ask for completion/help used, enjoyment (1–5), clarity (1–5), perceived repetition,
and a short note. The participant should play before reading maps, witness,
metrics or the assignment key. The bank can still be inspected afterward; this
is an honest blinding protocol in a trusted workbench, not an access-control claim.

Pending human responses stay pending. Neither a coding agent nor a playtester
may fill human ratings. Automated observations do not replace human calibration.
Unblind and interpret lane differences only after the ratings are retained.

Before collecting ratings, define the descriptive enjoyment count as technically
accepted candidates rated enjoyment 4 or 5. Report both distinct resolved identities
and human-stated equivalence groups; do not infer perceived distinctness from seeds.
Clarity is reported separately. Repair-field cost per enjoyed identity/group can
then be calculated; monetary cost remains unavailable. If equivalence judgments
or ratings are missing, the corresponding denominator remains pending rather than
being assumed. These are interpretation rules, not changes to game acceptance.
